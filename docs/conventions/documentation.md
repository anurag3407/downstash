# Documentation

> Docs are part of the deliverable. A task with stale docs is not done.

## Layout

`docs/README.md` is the index. `docs/codemap.md` lists every source file with
one line. `docs/progress.md` is the task tracker — claim a task as `IN
PROGRESS`, set it `DONE` with a summary, files, deviations, follow-ups and the
verification output.

Generated files:

| File                      | Regenerated by       |
| ------------------------- | -------------------- |
| `docs/engine/commands.md` | `pnpm docs:commands` |

`docs/engine/commands.md` starts with `<!-- GENERATED ... DO NOT EDIT. -->`.
Never hand-edit it.

## Frontmatter

Every doc except `codemap.md`, `progress.md` and generated files:

```markdown
---
title: Request lifecycle
status: stable # draft | stable | deprecated
last_updated: 2026-10-11
updated_by: P3-T2 # task ID of the last change
code_paths: # files this doc describes; all must exist
  - apps/gateway/src/app.ts
---
```

`updated_by` is required and must reference a task ID. That is how the next
agent knows whether a doc is current.

## Body shape

1. One-paragraph summary of what this is and when you would read it.
2. `## Where the code lives` — a table of concern → file.
3. `## How it works` — numbered steps, mermaid diagrams, copy-paste examples.
4. `## Gotchas` — the things that cost an afternoon.
5. `## Related` — sibling docs and ADRs.

Headings are sentence case. Code identifiers go in backticks. File references
are relative markdown links.

## What each change must update

| If you…                                         | Also update                                                    |
| ----------------------------------------------- | -------------------------------------------------------------- |
| add/rename/delete a source file                 | `docs/codemap.md`                                              |
| change a table, column or index                 | `docs/engine/schema.md`                                        |
| add/change a command                            | regenerate `docs/engine/commands.md`, add tests + corpus steps |
| add an error string                             | `docs/engine/errors.md` and `packages/protocol/src/errors.ts`  |
| change gateway routing, headers or status codes | `docs/gateway/protocol.md`                                     |
| add an env var                                  | `docs/ops/env-vars.md` + the `.env.example` files              |
| add a route or page                             | `docs/web/routes.md`                                           |
| add a feature module                            | `features/<x>/README.md` and `docs/web/features.md`            |
| change a UI component or token                  | `docs/design/components.md` / `tokens.md`                      |
| make an architectural decision not in the plan  | a new ADR                                                      |
| finish a task                                   | `docs/progress.md`                                             |

## Checks

`pnpm check:docs` verifies:

1. Every `.ts`/`.tsx` under `packages/`, `apps/` and `tooling/` has a `@file`
   header within its first five lines.
2. Every doc is reachable from `docs/README.md` — an orphaned doc fails.
3. Docs listed in the index exist.

`pnpm check:design` verifies the design-token rules over `apps/web`.

> [!NOTE]
> Plan §13.5 specifies stricter checks (codemap coverage both ways, frontmatter
> validation, link resolution, `commands.md` freshness). Only 1–3 are
> implemented. The generator for `commands.md` and the codemap are kept current
> by hand and by `pnpm docs:commands`; the rest is recorded as a follow-up in
> `docs/progress.md`.
